# Code Cinema by Megabagus

Gaya, panduan, dan alat produksi ada di library Code Cinema (github.com/pendekarAI/code-cinema). Skill ini mengambil library tersebut, lalu menyerahkan alur kerjanya ke panduan di dalam library. Library disimpan di `~/code-cinema`; di bawah ini `SETUP` berarti `$LIB/plugin/skills/code-cinema-by-megabagus/scripts/setup.sh`. Komunikasi dengan user dalam Bahasa Indonesia, kecuali user memilih bahasa lain.

0. **Bootstrap (hanya pemakaian pertama).** Jika `~/code-cinema/plugin/skills/code-cinema-by-megabagus/scripts/setup.sh` belum ada (dan user tidak sedang berada di dalam clone library), buat sparse clone berikut:

   ```sh
   git clone --quiet --depth 1 --filter=blob:none --sparse --branch main https://github.com/pendekarAI/code-cinema.git ~/code-cinema
   cd ~/code-cinema && git sparse-checkout set --no-cone '/*' '!/styles/*/demo/'
   git config codecinema.managed true
   ```

   Jika `~/code-cinema` sudah ada tetapi bukan library ini, berhenti dan beri tahu user (set `CODE_CINEMA_HOME` ke folder lain).

1. **Siapkan library.** Jalankan `sh ~/code-cinema/plugin/skills/code-cinema-by-megabagus/scripts/setup.sh` (atau `SETUP` di dalam clone tempat user berada). Perintah ini memperbarui library, menampilkan alat sistem yang belum ada (Node, ffmpeg, Python), dan mencetak `LIB=<path>` di baris terakhir.
2. **Pasang alat inti sejak awal.** Segera jalankan `sh "$LIB/plugin/skills/code-cinema-by-megabagus/scripts/setup.sh" deps`, di background jika bisa: pertama kali butuh beberapa menit. Tambahkan `deps voice` atau `deps music` belakangan, hanya jika film membutuhkannya (`$LIB/TECHNIQUE.md` §1). Laporkan alat sistem yang belum ada (Node 20+, ffmpeg 7+, Python 3.11+ atau uv) dalam satu putaran pertanyaan; jangan memasang software sistem sendiri. Gaya bertanda ✦ juga butuh generator gambar yang disediakan user (`$LIB/AGENTS.md`, Alur kerja, Brief). Paket yang dibutuhkan sebuah gaya (tercantum di `STYLE.md`-nya) dipasang sendiri, ke folder proyek.
3. **Ikuti panduan library.** Baca `$LIB/AGENTS.md` dan kerjakan sesuai isinya, mulai dari bagian **Mulai** (gaya milik user di `~/code-cinema-styles/`; jika skill dipanggil tanpa permintaan, tanyakan bahasa dulu, lalu pilihan jalurnya): mencari gaya atau membuat gaya sendiri, naskah dan voice over, satu putaran pertanyaan brief, treatment, produksi, dan penyerahan hasil.
4. **Naskah dulu, baru voice over (wajib, tepat setelah gaya jelas, sebelum brief lain dan treatment).** Jangan pernah memakai default diam-diam untuk naskah atau suara.
   1. **Satu `AskUserQuestion` dengan tiga pertanyaan** (lewati yang sudah disebut user):
      - **"Durasi"**: 30–60 detik (rekomendasi untuk promo dan teaser) · 1–5 menit · 5–20 menit (materi kelas, explainer panjang) · Layar Lebar: 20–60 menit (webinar atau modul kelas penuh, disusun dari 2–3 bagian). Maksimal 60 menit. Jika user memilih di atas 3 menit, sebutkan dalam satu kalimat bahwa prosesnya jauh lebih lama dan render bisa berlanjut dalam beberapa putaran; untuk Layar Lebar, bahwa film dikerjakan per bagian dalam beberapa sesi dan setiap bagian dikirim sebagai pratinjau.
      - **"Gaya naskah"**: Edukatif (rekomendasi untuk materi belajar: jelas, runtut, ramah pemula) · Formal / profesional · Santai / gaul · Storytelling (bercerita). Opsi Other untuk gaya lain (humor, inspiratif, jualan, dan sebagainya).
      - **"Voice over"**: Rekam suara sendiri (rekomendasi) · Suara AI perempuan atau laki-laki · Tanpa voice over (naskah tampil sebagai teks di layar + musik).
      - **Uji suara AI dulu** sebelum bertanya: pasang tingkat voice bila belum (`sh "$LIB/plugin/skills/code-cinema-by-megabagus/scripts/setup.sh" deps voice`), lalu `"$LIB/.venv/bin/python" -m edge_tts --text "uji suara" --voice id-ID-GadisNeural --write-media /tmp/vo_test.mp3`. Berhasil hanya jika file mp3 itu terbentuk dan tidak kosong. Tawarkan suara AI (`id-ID-GadisNeural` perempuan, `id-ID-ArdiNeural` laki-laki) hanya jika uji berhasil; jika gagal, sebutkan dalam satu kalimat dan ganti opsinya dengan "suara AI dibuat ulang lewat `build.sh` di komputer user".
   2. **Tulis naskah** sesuai gaya naskah, topik, bahasa, dan durasi; simpan sebagai `NASKAH.md`, `NASKAH.txt`, dan `vo/lines.json` di folder proyek. Kalimat pendek bernomor (v1, v2, …), satu gagasan per kalimat, hook di kalimat pertama, penutup yang menggema pembuka. Target jumlah kata ≈ durasi (detik) × 2,3 untuk bahasa Indonesia (2,1 untuk gaya santai atau storytelling; sisakan margin 5–8%); cantumkan perkiraan detik per kalimat dan totalnya. Di atas 60 detik, susun per bab (`[Hook]`, `[Peta isi]`, `[Bab N — Judul]`, `[Ringkasan]`, `[Penutup]`); di atas 5 menit kelompokkan bab ke dalam bagian (`[Bagian 1 — Judul]`, …) dengan rekap mini (`[Rekap Bagian 1]`), dan untuk film di atas 3 menit kirim `NASKAH.md` lengkap sebagai file (di chat cukup tabel per bab). Di `lines.json`, angka ditulis seperti diucapkan di `say` dan sebagai digit di `text`; tandai istilah asing beserta cara bacanya di `NASKAH.md`.
      - **`NASKAH.txt`**: teks polos UTF-8 tanpa markdown, untuk dibaca saat merekam atau ditempel ke teleprompter / aplikasi TTS. Isi berurutan: judul, gaya naskah, target durasi, dan total kata (± detik); `=== NASKAH UTUH ===` (label bagian seperti `[Hook]` atau `[Bab 1 — Judul]` di baris sendiri, lalu kalimat-kalimatnya disambung jadi satu paragraf, memakai kalimat yang diucapkan dari field `say`, tanpa nomor dan tanpa detik); `=== KALIMAT BERNOMOR ===` (`v1  kalimat`, …; hanya jika user merekam sendiri atau film di atas 60 detik); `=== CARA BACA ISTILAH ===` (hanya jika ada istilah asing); `=== PANDUAN REKAM ===` (ringkas). Setiap revisi memperbarui `NASKAH.md`, `NASKAH.txt`, dan `vo/lines.json` bersama-sama.
      - **Pakai "bagian", jangan "babak".** Kata "babak" tidak lazim dalam bahasa Indonesia, jadi jangan pernah dipakai di naskah: tidak di kalimat yang diucapkan, label bagian, tabel, kartu judul di layar, subtitle, maupun `CHAPTERS.txt`. Aturan ini mengalahkan istilah "babak" di panduan library (`AGENTS.md`, `DIRECTOR.md`, `TECHNIQUE.md`): baca "babak" di sana sebagai "bagian". Di film Layar Lebar, satuan besarnya sudah bernama "Bagian" (kartu "Bagian 2 — Judul", folder `bagian1/`), jadi kelompok bab di dalam tiap bagian ditulis "Segmen" (`[Segmen 1 — Judul]`) supaya satu kata tidak punya dua arti.
   3. **Kirim naskah dalam satu pesan, bersama pertanyaan brief**: naskah lengkap sebagai tabel (no, kalimat, perkiraan detik); **di bawah tabel, blok "Naskah siap salin"**, satu blok kode berisi naskah utuh yang sama dengan bagian NASKAH UTUH di `NASKAH.txt` supaya user tinggal menekan tombol copy (film di atas 3 menit: cukup Hook dan Bab 1 sebagai contoh, naskah utuh ada di file); lalu **`NASKAH.txt` sebagai file yang bisa diunduh** (di sesi cloud kirim dengan `SendUserFile`, di komputer user sebutkan path lengkapnya; kirim ulang versi terbaru setelah revisi); jika user merekam sendiri, sertakan panduan rekam (satu file utuh dengan jeda ±1 detik antar kalimat, atau satu file per kalimat bernama `v1`, `v2`, …; WAV/MP3/M4A; ruang hening, jarak mulut 15–20 cm, tanpa musik latar; boleh sedikit improvisasi karena timing film mengikuti rekaman); minta user menyetujui naskah atau menyebut revisinya.
   4. **Tunggu persetujuan naskah**, revisi bila diminta. Rekam sendiri: jangan memproduksi suara dan animasi sebelum file rekaman diterima (treatment dan style frame boleh dikerjakan sambil menunggu); setelah file tiba, potong per kalimat bila masih satu file (`ffmpeg silencedetect`), ambil timing per kata dengan `core/tts/asr_check.py`, lalu susun timeline, subtitle, dan potongan gambar dari rekaman itu. Suara AI: buat dari naskah yang disetujui, lalu periksa dengan `asr_check.py`. Tanpa voice over: naskah menjadi teks di layar, cek dengan `readcheck.mjs`.
5. **Film panjang (di atas 60 detik, maksimal 20 menit / 1.200 detik).** Ikuti kategori durasi di `$LIB/DIRECTOR.md` §1 (Durasi dan film panjang) dan cara membangunnya di `$LIB/TECHNIQUE.md` §13.
   - Durasi final = durasi voice over + ±1 detik pembuka + ±1,5 detik penutup, dibulatkan ke atas. Suara tidak pernah dipercepat atau dipotong; jika rekaman melewati batas kategori yang dipilih (20 menit, atau 60 menit untuk Layar Lebar), berhenti sebelum produksi dan minta keputusan: dipersingkat, direkam ulang, dipecah jadi episode, atau (di atas 20 menit dan masih ≤ 60 menit) diproduksi sebagai Layar Lebar (langkah 6).
   - Rekaman user di atas 5 menit: satu file per bab (`bab01`, `bab02`, …) dengan ruangan dan jarak mikrofon yang sama.
   - Kode per bab (`timeline/bab01.js`, …) dengan pustaka 8–12 jenis adegan dalam gaya itu; di atas 5 menit dibangun dan diuji per bagian. Musik per bab atau per bagian dari palet yang sama.
   - Render per chunk yang bisa dilanjutkan: `node core/render/chunks.mjs <proyek> --only 1,<chunk tengah>` untuk render uji, lalu tanpa `--only` untuk render penuh; `--redo` setelah mengubah bab tertentu. Di sesi cloud, jalankan di foreground dalam putaran `timeout 580 …` berulang sampai mencetak `done`, dan laporkan progres per putaran.
   - Kualitas bab terakhir sama dengan bab pertama: jangan menurunkan resolusi atau menyederhanakan animasi demi waktu render. Serahkan juga `CHAPTERS.txt` (timestamp bab untuk chapter YouTube).
6. **Layar Lebar (di atas 20 menit, maksimal 60 menit / 3.600 detik).** Film disusun dari 2–3 **bagian**, masing-masing ≤ 20 menit dan diproduksi seperti film Sangat panjang (`$LIB/DIRECTOR.md` §1, `$LIB/TECHNIQUE.md` §13).
   - Bagi di titik alami: setiap bagian punya satu pertanyaan besar dan satu kesimpulan, dimulai dan diakhiri di hening suara dan akhir frase musik. Bagian 1 membuka dengan hook dan peta isi seluruh film; bagian berikutnya dibuka kartu bagian ("Bagian 2 — Judul") dan rekap singkat; penutup film hanya di bagian terakhir.
   - Naskah: kerangka seluruh film disetujui di awal, ID kalimat dengan awalan bagian (`p1_b01_v01`). Rekaman user per bab dengan awalan bagian (`p1_bab01`, `p2_bab01`, …), ruangan dan jarak mikrofon sama; rekaman bagian 1 boleh dikirim lebih dulu.
   - Proyek: `bagian1/`, `bagian2/`, … (masing-masing folder film lengkap), `shared/` untuk pustaka adegan dan mesin gaya (disalin ke tiap bagian oleh `build.sh`), dan `PROGRES.md` yang mencatat status tiap bagian supaya bisa dilanjutkan di sesi lain.
   - Selesaikan satu bagian sampai lolos QC (render, mix, `mux.sh`), kirim ke user sebagai pratinjau, baru bangun bagian berikutnya.
   - Sambung: `sh core/render/join.sh <nama>.mp4 bagian1/bagian1.mp4 bagian2/bagian2.mp4 --chapters CHAPTERS.txt` (tanpa re-encode, menolak bagian yang formatnya berbeda, menanam chapter, melaporkan durasi dan loudness). Tonton ±10 detik di setiap sambungan. Serahkan film gabungan dan file per bagian.
   - Di atas 60 menit: jangan dibuat sebagai satu file; tawarkan seri video terpisah dengan gaya yang sama.
7. **Foley tidak pernah menutupi narasi.** Level foley selalu diatur terhadap suara narasi (rekaman user atau suara AI), bukan berdiri sendiri: setelah suara punya gain final, jalankan seluruh lapisan foley lewat `core.audio.sfx.under_voice(foley, voice, mask)`. Default-nya: momen paling keras foley ≥ 24 dB di bawah narasi saat bicara (pita konsonan 1–4 kHz dikosongkan), ≥ 10 dB di bawah narasi di jeda, dan desis di atas 7 kHz dipangkas.
   - Gaya dengan foley tajam menetapkan angka sendiri di `STYLE.md`-nya: **Sketchnote** (goresan pena) 24/10 dB; **Copperplate Engraving** (pahat burin di pelat tembaga, goresan arsir) 26/12 dB dengan low-pass 6,5 kHz. Gaya pena, pensil, spidol, atau pahat lain memakai minimal angka default.
   - Sebelum mux, cek `speech_gap_db` yang dicetak (≥ 22) dan dengarkan satu kalimat di bagian foley paling ramai. Detail: `$LIB/TECHNIQUE.md` §6 dan QC di `$LIB/DIRECTOR.md`.
